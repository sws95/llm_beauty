# 화장품 추천을 위한 상품 속성 자동 추출 (OCR + 규칙 + LLM)

판매자가 비워둔 화장품 속성(제형·피부타입·효능·성분)을 상품 사진과 설명에서 자동으로 채우고,
그 속성이 추천 성능에 주는 영향을 검증하는 프로젝트입니다.

> 진행 상태: 속성 추출·평가, 비즈니스 분석, 추천 실험(텍스트 임베딩 비교 포함) 완료

### 한눈에 보기

- **추출:** 판매자가 17%만 채운 효능을 자동 추출로 76%까지 채움. LLM이 찾은 근거로 라벨을 검증하는 방식이 규칙 대비 효능 정밀도 +23%p (판매자 정답이 절반 가까이 누락돼 있어, 사람 기준으로는 90% 이상)
- **분석 (414만 인증구매 리뷰):** 연속 구매의 약 90%는 브랜드를 바꾸는 구매이고, 브랜드를 바꿔도 같은 핵심 성분을 4~6배 더 삼(티트리 6.2배, 병풀 5.2배, 달팽이 4.5배). 신호는 설명 전체가 아니라 상품명의 핵심 성분·메인 효능에 있음
- **추천:** ID 드롭아웃으로 신상품 Recall 3배(전체 −4%). 올리브영이 쓰는 방식인 **상품 설명 텍스트 임베딩이 구조화 속성보다 신상품 Recall +47%로 우세**했고, 둘을 합치면 오히려 하락 → 속성의 역할을 추천 점수가 아니라 필터·추천 이유·데이터 보정·분석으로 재정의
- **검증 태도:** 시드 5개 반복으로 단일 시드 결론 2개 철회, 브랜드 교란 변수 통제, 가설과 다른 결과도 그대로 보고

## 1. 문제 정의

화장품은 피부타입·제형·효능·성분이 구매를 좌우하지만, 판매자가 이 속성을 채우지 않는 경우가 많습니다.

| 속성 | 판매자 입력률 (스킨케어 약 20만 개) |
|---|---|
| 제형 (Item Form) | 62.8% |
| 피부타입 (Skin Type) | 37.7% |
| 효능 (Product Benefits) | 19.0% |
| 성분 (Active Ingredients) | 15.3% |

반면 이 정보는 상품 **패키지 사진과 설명**에 대부분 적혀 있습니다.

**가설:** 사진과 설명에서 속성을 자동 추출해 빈칸을 채우면, 구매 이력이 적은 상품(콜드스타트)의 추천 품질이 개선된다.

## 3. 속성 정의 (정규화 어휘)

판매자 입력값은 표기가 제각각이라(예: 효능 고유값 14,691개) 고정 어휘로 정규화했습니다.

| 속성 | 어휘 | 정규화 성공률 |
|---|---|---|
| 제형 (1개) | cream, lotion, gel, oil, bar_soap, liquid, balm, serum, foam, mask_sheet, spray_mist, powder, clay_scrub, stick | 97.3% |
| 피부타입 (복수) | all, dry, oily, combination, normal, sensitive, acne_prone, mature | 99.8% |
| 효능 (복수) | hydrating, anti_aging, exfoliating, soothing, smoothing, cleansing, nourishing, brightening, antioxidant, sun_protection, acne_care | 91.1% |
| 성분 (복수) | 대표 활성 성분 15개 (retinol, niacinamide, vitamin_c, hyaluronic_acid, salicylic_acid 등) | 45.0% (*) |

(*) 글리세린·비타민E 같은 베이스 성분은 구별력이 없어 의도적으로 제외. 45%는 "대표 활성 성분이 들어 있는 상품" 비율

**정규화 원칙**
1. 같은 뜻의 다른 표기는 하나로 (moisturizing, hydration → hydrating)
2. 추천에 쓸모 있는 수준으로만 나누기
3. 효능이 아닌 성질(hypoallergenic)과 구별력 없는 베이스 성분은 제외
4. 피부타입의 기본 네 가지(dry·oily·combination·normal)를 모두 나열한 경우는 "all"과 같게 처리

## 4. 평가 설계

- **평가 샘플:** 상호작용에 등장하고 판매자 정답이 하나 이상 있는 상품 1,000개 (Face 500 / Body 500)
- **빈칸 샘플:** 피부타입·효능이 모두 비어 있는 상품 100개 → 채움률 측정
- **사진:** 1,100개 상품의 전체 사진 4,887장 (상품당 평균 4.4장, 고해상도 88.2%)
- **사진 조합 비교:** 대표 사진만 / 대표 + 랜덤 2장 / 고해상도 전체(메인) / 저해상도 포함(참고)
  - 사진을 한 장씩 추출한 뒤 상품 단위로 합쳐서, 추가 추출 없이 조합별 비교가 가능하도록 설계
- **세그먼트별 평가:** Face와 Body를 나눠서 평가 (피부타입은 Face에서, 제형은 Body에서 중요도가 다를 것으로 예상)
- **판매자 정답 검증:** 오답을 직접 검수해 "판매자 정답이 불완전"(A) / "예측이 틀림"(B) / "애매"(C)로 분류하고 보정 정밀도 계산

## 5. 방법론의 변천과 판단

### 5-1. VLM으로 사진에서 직접 추출 (Qwen3-VL-2B, 로컬)

| 문제 | 관찰 | 대응 |
|---|---|---|
| 지어내기 | 읽은 글자가 없는데도 "all", "hyaluronic_acid" 같은 흔한 값을 채움 | 읽은 문구(visible_text)를 먼저 쓰게 한 뒤 라벨을 고르도록 프롬프트 변경 + 읽은 문구에 근거가 있는 라벨만 인정 |
| 출력 잘림 | 전성분표를 전부 옮기다 생성 길이 한도에 걸려 JSON이 깨짐 | 잘린 출력에서 읽은 문구만 복구해 규칙으로 라벨링 |
| 속도 | RTX 3070에서 한 장 44~53초 → 768px로 줄여도 약 30초. 4,885장에 수십 시간 | **읽기와 판단을 분리하기로 결정** |

### 5-2. OCR + 규칙 (PaddleOCR PP-OCRv6)

- **속도:** 한 장 **0.19초** (VLM 대비 약 150배 이상), 4,885장 약 15분
- 좌표를 이용해 읽는 순서 정렬, 칼럼 분리, 줄 끝 하이픈 이어붙이기, 큰 글씨([BIG]) 표시
- 줄바꿈으로 끊긴 성분명("Niacin / amide")은 공백을 제거한 버전에서도 매칭

### 5-3. 오답 검수 → 규칙 v2

규칙 v1의 오답 30개를 직접 검수한 결과:

| 속성 | A (정답 불완전) | B (규칙 오류) | 보정 정밀도 |
|---|---|---|---|
| 제형 | 0 | 6 | 측정값 그대로 (전부 진짜 오류) |
| 피부타입 | 5 | 5 | 약 35% → **약 67%** |
| 효능 | 4 | 5 (+C 1) | 약 31% → **약 59%** |

**판매자 정답이 불완전해서 측정 정밀도가 실제보다 크게 낮게 나온다**는 것을 확인했고,
B(규칙 오류)는 다섯 가지 패턴으로 묶였습니다.

| 오류 패턴 | 예시 | v2 대응 |
|---|---|---|
| 부정 표현 | "Soap-Free" → 비누, "No mineral oil" → 오일 | 부정 표현 뒤 제거 |
| 사용법·주의 문구 | "Apply to clean and dry skin" → 건성 | Directions/Warning 구역 제외 |
| 성분명이 제형으로 | "Coconut Oil" → 제형 oil | 전성분 구역은 성분에만 사용, 제형은 상품명 우선 |
| 단어 일부 매칭 | "massaging" 안의 "aging" → 안티에이징 | 단어 경계 추가 |
| 우선순위 | "Clay Mask" → mask | clay를 mask보다 우선 |

**v1 → v2 (350개, 고해상도 전체)**

| | v1 | v2 |
|---|---|---|
| 제형 정확도 (Face / Body) | 62.4% / 54.6% | **75.3% / 66.7%** |
| 피부타입 정밀도 / 재현율 (Face) | 34.7% / 36.7% | 40.6% / 28.9% |
| 효능 정밀도 / 재현율 (Face) | 31.4% / 72.9% | 33.9% / 67.8% |

제형은 원인을 정확히 짚어 크게 개선됐고, 피부타입·효능은 정밀도가 오르는 대신 재현율이 줄어드는 트레이드오프가 나타났습니다.
효능 정밀도가 크게 오르지 않은 것은 판매자 정답이 불완전해 **측정 가능한 정밀도에 천장**이 있기 때문으로 판단해, 규칙 개선은 여기서 멈췄습니다.

### 5-4. OCR 글자 + 텍스트 LLM

규칙이 못 하는 문맥 판단(돌려 말한 효능, 부정, 사용법과 효능 구분)을 LLM에 맡기기 위해,
상품명·판매자 특징·설명·OCR 문구를 상품당 한 번 텍스트 LLM(Qwen3-VL-2B, 사진 없이)에 입력했습니다.

**역할 분담:** 성분은 이름이 그대로 적혀 규칙이 강하고, LLM은 전성분을 통째로 나열하는 문제가 있어 **성분은 규칙, 제형·피부타입·효능만 LLM**에 맡김

**비교한 네 가지 방식**

| 방식 | 라벨 결정 방법 |
|---|---|
| 규칙 v2 | LLM 없이 OCR 글자 전체에 규칙 적용 |
| LLM 원출력 | LLM이 고른 라벨 그대로 |
| 근거 검증 | LLM이 고른 라벨 중 근거 문구에 뒷받침되는 것만 |
| 근거 → 규칙 | LLM 라벨은 버리고, LLM이 찾은 근거 문구에 규칙 적용 |

**구조화 출력(enum) 적용:** outlines로 허용값을 enum으로 강제하고 근거를 먼저 쓰게 한 결과, 형식 오류와 전성분 나열은 사라졌지만
2B 모델이 **같은 값을 반복하거나 근거와 무관한 라벨**을 고르는 현상이 나타남(제약 디코딩의 부작용).
반면 **근거 문구는 정확히 찾아내** → "LLM은 관련 문구 찾기, 규칙은 라벨링"으로 역할을 나눈 근거 → 규칙 방식이 가장 유력

**LLM 출력 신뢰성 확보 장치**
- 모든 생성은 샘플링 끔(temperature 0과 같은 효과) → 같은 입력에 같은 출력
- 근거 문구가 입력에 실제로 존재하고, 그 문구 안에 라벨 키워드가 있어야 라벨 인정
- 잘린 JSON은 완성된 필드·항목까지 복구

## 6. 추출 결과

### 6-1. OCR + 규칙 v2 (1,100개, 고해상도 전체)

| | 제형 정확도 | 피부타입 P / R | 효능 P / R | 성분 P / R |
|---|---|---|---|---|
| Face | 71.1% | 45.2% / 28.5% | 34.7% / 63.2% | 49.7% / 62.9% |
| Body | 68.5% | 50.7% / 13.6% | 33.3% / 71.1% (*) | 75.8% / 64.1% |

(*) Body 효능은 정답 32개로 참고용. P = 판매자 정답 기준 정밀도 (실제보다 낮게 측정됨, 6-3 참고)

- **대표 사진만으로는 부족하다:** 정보가 나온 상품 중 피부타입 64.8%, 효능 62.9%, 성분 59.9%는 대표 사진이 아닌 다른 사진에서 추가로 나옴
- **사진 수와 정확도의 트레이드오프:** Face 효능 기준 대표 사진만 P 46.9% / R 32.5%, 전체 사진 P 34.7% / R 63.2%
- **빈칸 채움:** 판매자가 피부타입·효능을 모두 비워둔 상품에서 효능 74.4%, 제형 76.8%, 성분 40.2%, 피부타입 34.1%
- 상품명 피부타입 반영과 민감성 동의어(irritated, eczema 등) 복구로 Face 피부타입이 P 42.3% → 45.2%, R 22.4% → 28.5%로 동시에 개선
- 350개 샘플과 1,100개 결과가 몇 %p 이내로 일치

### 6-2. 네 가지 방식 비교 (947개, 판매자 정답 기준, Face)

| 방식 | 제형 정확도 (답한 비율) | 피부타입 P / R | 효능 P / R |
|---|---|---|---|
| 규칙 v2 | 71.1% (87%) | 45.2% / 28.5% | 34.7% / 63.2% |
| LLM 원출력 | **52.9%** (100%) | 44.1% / 38.5% | 39.6% / 66.5% |
| **근거 검증** | 73.9% (64%) | **56.9%** / 21.6% | **57.8%** / 45.2% |
| **근거 → 규칙** | 72.1% (79%) | 60.6% / 17.4% | 47.0% / 54.8% |

Body 제형: 규칙 v2 68.5% / LLM 원출력 52.7% / 근거 검증 83.3% / 근거 → 규칙 78.5%

- **LLM을 그대로 쓰면 규칙보다 못하다.** 제형 정확도 53%, 빈칸 100% 채움은 근거 없는 "all" 남발 때문에 부풀려진 숫자
- **근거로 검증하면 규칙보다 확실히 낫다.** 효능 정밀도 +23%p, 피부타입 +12%p
- **LLM은 근거는 맞게 찾고 라벨은 틀리게 고른다.** 근거에 "soap"을 적고 라벨은 liquid를 고르는 식 → 근거 → 규칙이 제형에서 강한 이유
- 근거 → 규칙은 피부타입에서 "oily", "normal to dry"처럼 짧은 근거를 놓침 → 피부타입은 근거 검증이 강함

### 6-3. 사람 정답 기준 재평가 (30개, 예비)

판매자 정답을 출발점으로 상품명·근거 문구를 보고 고친 1차 판정 기준입니다. 사진 확인 전이고 근거 문구를 참고해 판정해 근거 기반 방식에 유리할 수 있어, 방향 확인용입니다.

| 효능 | 판매자 기준 P (947개) | 사람 기준 P | 사람 기준 R |
|---|---|---|---|
| 규칙 v2 | 34.7% | 67.2% | 61.9% |
| LLM 원출력 | 39.6% | 61.6% | 84.1% |
| 근거 검증 | 57.8% | **100%** | 49.2% |
| 근거 → 규칙 | 47.0% | **92.3%** | 57.1% |

- **판매자 기준 평가는 정밀도를 절반 가까이 과소평가**하고 있었음
- 30개 상품 중 **판매자가 효능을 채운 상품은 0개**
- 피부타입은 근거 검증이 판매자와 같은 재현율(50%)에 더 높은 정밀도(88.9% vs 84.2%)
- 판매자 오입력 사례: Dove Beauty Bar → cream, Foaming Wash → oil, Cleansing Foam → cream, 스크럽·토너 → lotion

### 6-4. 최종 조합

|---|---|
| 제형 | 상품명 → 없으면 근거 → 규칙 |
| 피부타입 | 근거 검증 ∪ 상품명 피부타입 |
| 효능 | 근거 검증 (정밀도 우선) |
| 성분 | 규칙 v2 |

## 7. 비즈니스 분석 — 왜, 그리고 어디에 속성 기반 추천이 필요한가

스킨케어 상품 181,602개, 인증구매 4,144,985건 (`business_analysis.py`, 결과 전문: `data_skincare/analysis_report.md`)

> 18만 개 전체의 속성은 **판매자 입력 + 상품명·특징·설명에 규칙 v2를 적용**해 채웠습니다. LLM·OCR은 상품당 수 초가 걸려 1,000개 샘플의 추출 방식 비교(6장)에만 사용했습니다.

### 7-1. 판매 쏠림과 콜드스타트 압력

- 상위 1% 상품이 구매의 **43.8%**, 상위 10%가 **80.5%** (지니계수 0.85)
- **상품의 62.0%가 구매 5건 미만**
- 최근 1년 구매 371,534건 중 그 전에 구매 0건이던 상품으로 간 구매 **9.2%**, 5건 미만 **15.8%**, 20건 미만 **26.7%**

→ 구매 6건 중 1건은 이력 기반 추천이 도와줄 수 없는 상품에서 일어남

### 7-2. 고객은 같은 속성을 반복해서 사는가

유저의 연속 구매 쌍(구매 간격 1일 이상, 세트 구매 제외)에서 속성이 겹치는 비율을, 두 번째 상품을 **구매 분포(인기도)대로 무작위로 뽑았을 때**와 비교

| 속성 | Face 배수 | Body 배수 |
|---|---|---|
| 브랜드 | **14.0배** | **16.0배** |
| 제형 | 1.39배 | 1.61배 |
| **핵심 성분 (상품명)** | **1.38배** | **1.36배** |
| 성분 (전성분 포함) | 1.26배 | 1.29배 |
| **메인 효능 (상품명)** | **1.19배** | 1.08배 |
| 피부타입 ("all" 제외) | 1.15배 | 1.08배 |
| 효능 (설명 전체) | 1.04배 | 1.04배 |

**상품명에 있는 효능·성분이 진짜 신호, 설명과 전성분에 섞인 부가 정보는 신호를 희석한다**

| 라벨 | 설명·전성분 전체 → 상품명만 (Face) |
|---|---|
| 메인 효능: 여드름 케어 | 1.38 → **2.32배** (Body 1.76 → 3.00배) |
| 메인 효능: 자외선 차단 | 1.62 → **2.35배** |
| 메인 효능: 진정 | 1.15 → 1.73배 |
| 핵심 성분: 글리콜산 | 2.14 → **3.88배** |
| 핵심 성분: 펩타이드 | 1.92 → **3.29배** |
| 핵심 성분: 나이아신아마이드 | 1.97 → 2.67배 |
| 효능: 보습 | 1.03 → 1.09배 (스킨케어 기본 기능이라 선택 기준이 아님) |

- 클렌저·선크림 설명에도 "moisturizing", "soothing"이 들어가 거의 모든 상품이 보습·진정을 가짐 → 설명 전체로 보면 효능은 무작위와 차이 없음(1.04배)
- 흔한 라벨(보습, 피부타입 "all", 히알루론산)은 1.0~1.17배로 신호가 없고, 특징적인 라벨일수록 강함

### 7-3. 브랜드를 통제하면? — 브랜드가 다른 쌍만

속성 신호가 사실 "같은 브랜드 재구매"였는지 확인하기 위해, 실제 쌍과 무작위 쌍 모두 **이전 상품과 브랜드가 다른 경우만** 남겨 다시 계산

| 속성 | Face 전체 쌍 → 브랜드 다른 쌍 | Body |
|---|---|---|
| 제형 | 1.39 → 1.31배 | 1.61 → 1.49배 |
| 핵심 성분 | 1.38 → 1.25배 | 1.36 → 1.21배 |
| 메인 효능 | 1.19 → 1.16배 | 1.08 → 1.04배 |
| 피부타입 | 1.15 → 1.11배 | 1.08 → 1.05배 |

**특징적인 성분은 브랜드를 바꿔도 강하게 남는다 (핵심 성분, 브랜드 다른 쌍, Face)**

| 성분 | 배수 |
|---|---|
| 티트리 | **6.20배** |
| 병풀 | **5.16배** |
| 달팽이 점액 | **4.47배** |
| 글리콜산 | 3.02배 (3.88배에서 감소) |
| 세라마이드 | 3.01배 |
| 살리실산 | 2.66배 |
| 나이아신아마이드 / 펩타이드 | 1.75배 (2.67 / 3.29배에서 크게 감소) |

메인 효능도 여드름 케어 2.13배, 자외선 차단 2.09배로 유지

→ 속성 신호의 **일부는 브랜드였지만**(모든 배수 감소), 브랜드와 무관한 **성분 충성도**가 분명히 존재함

### 7-4. 브랜드 × 속성 — 둘이 겹치면 더 강해지는가

연속 구매 쌍을 (같은/다른 브랜드) × (같은/다른 속성) 네 칸으로 나누고, 시너지 = 배수(같은 브랜드·같은 속성) ÷ (배수(같은 브랜드) × 배수(같은 속성))로 계산

| | 시너지 | 같은 브랜드 재구매 시 속성 유지 | 브랜드 전환 시 속성 유지 (실제 / 무작위) |
|---|---|---|---|
| Face 핵심 성분 | 0.73 | 67.9% | 41.5% / 33.3% (1.25배) |
| Face 메인 효능 | 0.87 | 64.5% | 49.8% / 42.9% (1.16배) |
| Face 제형 | 0.64 | 34.7% | 19.3% / 14.7% (1.31배) |
| Body 핵심 성분 | 0.72 | **93.7%** | 56.6% / 46.7% (1.21배) |
| Body 제형 | 0.72 | 45.0% | 21.9% / 14.7% (1.49배) |

- **시너지가 모두 1보다 작다(0.64~0.94):** 같은 브랜드를 다시 사면 속성은 이미 따라온다(같은 라인 재구매). 같은 브랜드 안에서는 속성이 같든 다르든 배수가 비슷함(Face 핵심 성분 11.5배 vs 12.1배) → 브랜드 × 속성 조합은 별도 신호가 아니며, 둘을 **더하는** 모델 구조가 적절
- **연속 구매의 80~90%는 브랜드를 바꾸는 구매:** 같은 브랜드 재구매는 배수는 크지만 비중은 10~20%. 브랜드를 바꾸는 순간 고객을 다음 상품으로 이어주는 것은 속성(제형 1.3~1.5배, 핵심 성분 1.2~1.25배, 특징 성분 4~6배)

### 7-5. 판매자 입력 품질

| 속성 | 판매자 채움률 | 판매자 + 텍스트 규칙 |
|---|---|---|
| 제형 | 61.6% | 87.7% |
| 피부타입 | 37.4% | 53.4% |
| **효능** | **17.0%** | **75.8%** |
| 성분 | 6.6% | 28.9% |
| 메인 효능 (상품명) | — | 47.5% |
| 핵심 성분 (상품명) | — | 14.1% |

- 피부타입을 채운 상품 중 **42.8%는 "all"만** 입력
- 인기 상품일수록 조금 더 채우지만(효능 하위 20% 15.6% → 상위 20% 21.3%) 대부분 비어 있음 (큰 브랜드 효과가 섞인 상관관계)
- 판매자 제형과 상품명·설명 기반 제형이 둘 다 있는 100,342개 중 **28.6% 불일치**

### 7-6. 분석 결론

1. 콜드스타트는 실제 문제 → 상품 속성으로 이력을 대신해야 함
2. **브랜드가 가장 강한 신호**, 속성은 **브랜드를 바꾸는 순간**의 연결고리
3. **상품명에 있는 효능·성분만 쓰고**, 흔한 라벨은 가중치를 낮춰야 함
4. 속성의 진짜 신호는 **소수의 특징적 성분·효능**(달팽이, 병풀, 티트리, 여드름 케어, 자외선)에 몰려 있음

## 8. 추천 실험

`rec_experiment.py` · 속성: 판매자 입력 + 텍스트 규칙 v2 (7장과 동일, LLM 미사용)

### 8-1. 설계

- **모델:** 피처 BPR (LightFM과 같은 구조). 상품 벡터 = 상품 ID 벡터 + 속성 필드별 평균 임베딩의 합. 학습 기간에 팔린 적 없는 상품은 ID 부분을 0으로 두고 속성만으로 점수를 받음
- **7장 결론 반영:** 효능은 메인(상품명)과 설명 속 효능을 별도 필드로, 성분도 핵심(상품명)과 나머지를 구분 가능, 피부타입 "all" 제외, 흔한 라벨은 필드 내 IDF로 가중치 낮춤
- **분할:** 시간 기준, 마지막 10% 기간을 평가(학습 421,746건 / 평가 37,835건). 평가 구매의 **19.5%가 학습 기간에 한 번도 안 팔린 상품**
- **과적합 방지:** 유저·상품 벡터 L2, 학습 기간의 마지막 10%로 조기 종료 후 최적 에폭으로 전체 재학습
- **ID 드롭아웃:** 학습 시 일정 확률로 상품 ID 부분을 꺼서 속성만으로도 점수를 매기도록 학습 (DropoutNet 아이디어)
- **평가:** Recall@20, NDCG@20 / 학습 기간 판매 수 구간별 Recall / **신상품 전용 순위**(판매 5건 미만 상품끼리만 순위)
- **시드 5개(7, 42, 123, 2024, 9999)** 평균 ± 표준편차

### 8-4. 텍스트 임베딩과의 비교

"임베딩 모델에 설명을 통째로 넣으면 되는데, 왜 속성을 따로 뽑는가?"에 답하기 위한 비교입니다. 상품명 + 특징 + 설명(평균 727자)을 `BAAI/bge-small-en-v1.5`(384차원)로 임베딩해, 같은 모델 구조(드롭아웃 0.3, 핵심 성분만)에서 비교했습니다. (`build_text_emb.py`, 시드 5개)

| 모델 | 전체 Recall@20 | 신상품 전용 Recall@20 | 완전 신상품 Recall | 인기 상품(20건+) Recall |
|---|---|---|---|---|
| 인기순 | 0.0210 | 0 | 0 | 0.0481 |
| 판매자 속성 | 0.0232 ± 0.0010 | 0.0171 ± 0.0021 | 0.0028 | 0.0492 |
| 자동 추출 속성 | 0.0239 ± 0.0015 | 0.0175 ± 0.0034 | 0.0031 | 0.0507 |
| **텍스트 임베딩** | **0.0304** ± 0.0009 | **0.0257** ± 0.0026 | **0.0059** | **0.0626** |
| 속성 + 텍스트 임베딩 | 0.0274 ± 0.0014 | 0.0215 ± 0.0030 | 0.0035 | 0.0587 |
| 임베딩 유사도 (학습 없음) | 0.0178 | 0.0218 | **0.0194** | 0.0170 |

- **텍스트 임베딩이 모든 구간에서 우세:** 자동 추출 속성 대비 전체 +27%, 신상품 전용 +47%, 완전 신상품 약 2배. 차이가 표준편차보다 훨씬 큼
- **속성을 더하면 오히려 하락:** 임베딩이 이미 설명 전체를 담고 있어 속성은 새 정보가 거의 없고, 잡음 섞인 라벨이 학습을 방해함 (8-3에서 피부타입·나머지 성분이 잡음이었던 것과 같은 결과)
- **완전 신상품은 학습 없는 임베딩 유사도가 최강:** 유저가 산 상품과 설명이 비슷한 상품을 찾는 방식이 학습 모델보다 3배 이상 잘 맞힘. 대신 인기 상품은 학습 모델이 3배 이상 강함 → **신상품 영역은 콘텐츠 기반, 기존 상품은 학습 모델**로 나누는 하이브리드가 적합

### 8-5. 결론

1. **신상품 노출을 늘린 핵심은 ID 드롭아웃이었다.** 드롭아웃 0.3에서 전체 성능은 판매자 모델 대비 −4%, 완전 신상품 Recall은 **약 3배**(0.0015 → 0.0047). 비율 하나로 신상품 노출과 전체 정확도의 균형을 조절할 수 있다.
2. **브랜드가 압도적이고, 다른 속성은 평균 지표에서 통계적으로 유의미한 추가 효과가 없었다.** 7-3·7-4의 분석이 이유를 설명한다. 속성 신호의 일부는 브랜드와 겹치고, 남은 진짜 신호는 소수의 특징적 성분·효능과 브랜드를 바꾸는 일부 구매에 몰려 전체 평균 Recall에 묻힌다.
3. **자동 추출 속성은 판매자 속성을 넘지 못했다.** 텍스트 규칙으로 채운 잡음 섞인 속성은 결과의 표준편차를 2~5배 키웠고, **상품명의 핵심 성분처럼 정확한 속성만 남겼을 때** 판매자 속성과 같은 수준(0.0181 vs 0.0185)이 되었다. 속성은 양보다 정확도가 중요하다.
4. **추천 정확도는 텍스트 임베딩이 구조화 속성을 이겼다.** 속성이 추천을 개선한다는 가설은 지지되지 않았다. 대신 속성은 임베딩 벡터가 못 하는 일, 즉 **필터(피부타입·성분 조건), 추천 이유 제시, 판매자 입력 보정, 고객 행동 분석**(브랜드 전환 시 성분 충성도 발견)에서 역할이 분명하다.
5. **시드 하나로 본 결론 두 개를 시드 다섯 개로 확인해 철회했다.** "드롭아웃은 속성이 촘촘할 때만 효과가 있다"(판매자 속성에도 드롭아웃이 효과 있음), "메인 효능이 브랜드 다음으로 중요하다"(5개 시드에서 재현되지 않음).

### 8-6. 서비스 적용 관점

- 기본 추천: 브랜드와 구매 이력 중심
- **브랜드를 바꾸는 순간**(새 브랜드 탐색, 신상품 영역): 핵심 성분·메인 효능·제형이 같은 **다른 브랜드** 추천
- 특정 성분(달팽이, 병풀, 티트리 등)을 반복 구매하는 고객에게 "같은 성분, 다른 브랜드" 영역을 별도로 제공
- 신상품 노출 비중은 ID 드롭아웃 비율로 조절
- **점수는 텍스트 임베딩 기반 모델**, 신상품 전용 영역은 **학습 없는 임베딩 유사도**, 추출한 속성은 **필터와 추천 이유 문구**에 사용

## 9. 한계

- **추천 실험의 속성은 LLM이 아닌 텍스트 규칙으로 채움:** LLM·OCR은 1,000개 샘플의 방식 비교에만 적용. "LLM 추출 속성이 추천을 개선하는가"는 아직 검증하지 못함
- **판매자 정답의 불완전성:** 누락·오입력·"all" 과다 사용 → 사람 정답 재평가는 30개, 사진 확인 전 예비 결과
- **평가 기간 하나로만 평가:** 시드 5개로 학습 흔들림은 확인했지만, 평가 기간이나 유저 표본에 따른 흔들림(부트스트랩 신뢰구간)은 미확인
- **비교 조건 일부 불일치:** 판매자 속성은 드롭아웃 0.5로만 실험(0.3 미실험), ID만 모델과 IDF 비교는 시드 1개
- **임베딩 모델 하나로만 비교:** bge-small 한 가지로 비교함. 더 큰 모델(bge-base, Qwen3-VL-Embedding)이나 한국어 데이터(bge-m3)에서 결론이 같은지는 미확인
- **평균 지표의 한계:** 소수 고객에게 큰 효과가 전체 평균 Recall에 묻힘 → 세그먼트 평가 필요
- **카테고리 잡음:** 향수, 헤어 보닛, 반려동물 귀 세정제 등 비스킨케어 상품 혼입
- **문맥 의존 표현과 이름 속임:** "revitalizing"(샤워젤 vs 크림), "tighten pores", 두피·모발 문장, "Masque Bar"·"Cocoa Butter Formula" 같은 이름
- **연속 구매 분석:** 리뷰 작성 시점을 구매 시점으로 사용, 동일 상품 재구매는 중복 제거로 제외

## 11. 재현 방법

**환경**
- 전역 Python 3.13: PyTorch(cu126), transformers, outlines (Qwen3-VL-2B, 추천 실험)
- `.venv_paddle`: paddlepaddle-gpu 3.2.2(cu126), paddleocr (OCR 전용, 라이브러리 충돌 방지)
- GPU: RTX 3070 8GB (Windows에서는 Triton이 없어 torch.compile 비활성화)

**실행 순서**
```bash
# 1. 데이터 준비
python build_skincare_data.py --meta meta_Beauty_and_Personal_Care.jsonl --review Beauty_and_Personal_Care.jsonl --min_user 5
python prepare_eval_sample.py --n_per_seg 500 --n_missing 100
python extract_per_image.py --download

# 2. OCR (.venv_paddle) + 규칙 평가
python ocr_paddle.py --n_per_seg 500 --n_missing 100
python extract_per_image.py --eval --source ocr2

# 3. 텍스트 LLM (전역 환경)
python llm_text.py --run --structured --n_per_seg 500 --n_missing 100 --model_path <Qwen3-VL-2B-Instruct 경로>
python llm_text.py --eval --structured
python llm_text.py --compare --structured --n_audit 30     # '사람 정답' 수정 후
python llm_text.py --compare_score --structured

# 4. 비즈니스 분석
python business_analysis.py --fill
python business_analysis.py --market --consistency --seller
python business_analysis.py --consistency --cross_brand     # 브랜드 통제
python business_analysis.py --brand_attr                    # 브랜드 × 속성
python business_analysis.py --reviews --review_path Beauty_and_Personal_Care.jsonl

# 5. 추천 실험 (Windows PowerShell은 한글 출력을 위해 먼저
#    [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $env:PYTHONIOENCODING="utf-8")
python rec_experiment.py --variants pop seller seller+drop filled+drop --seeds 7 42 123 2024 9999
python rec_experiment.py --variants filled+drop --active_mode main --seeds 7 42 123 2024 9999
python rec_experiment.py --variants filled+drop0.3 filled+drop0.5 filled+drop0.7 --seeds 7 42 123 2024 9999
python rec_experiment.py --variants filled+drop --ablation --seeds 7 42 123 2024 9999

# 6. 텍스트 임베딩 비교
python build_text_emb.py
python rec_experiment.py --variants pop emb_knn seller+drop0.3 filled+drop0.3 emb+drop0.3 filled_emb+drop0.3 --active_mode main --seeds 7 42 123 2024 9999
```
